OASIS — software images for the browser

An OASIS image is a recipe, not an archive: the world a program needs (DOS, Linux user space or Win32, all answered in JavaScript), the machine, and layers of files fetched from where their authors published them — Debian's archive, idgames, Docker Hub, the examples of this repository. The program runs as it was published, its x86 code by MIRAGE. Nothing below is copied in; each layer says where it comes from.

node tools/oasis.mjs serve --open          every image, in the Machines page, at home
node tools/oasis.mjs run linux/mirage         one image, in a window of its own
node tools/oasis.mjs run linux/debian-bookworm -c 'ls /'      in the terminal
node tools/oasis.mjs pull linux/doom-1994       fetch its layers into ~/.cache/oasis

From Docker Hub

An i386 image of Docker Hub's, run here with no Docker: its linux/386 manifest and layers come through this site's relay (anonymous, Docker Hub's public i386/ images only), its layers are laid over one another in the page, and its own command starts on the Linux machine's console. Many images need what MIRAGE-LINUX has not yet — a network, above all — and a server waits for clients it cannot get.

For instance i386/alpine, i386/busybox, i386/python:3.12-alpine, i386/debian:bookworm-slim. On a computer: node tools/oasis.mjs import docker://i386/alpine.

Your files in this browser

What a Linux image's programs wrote in its home directory ($HOME), kept here between visits and laid over the image when it starts again. Nothing leaves this browser.
