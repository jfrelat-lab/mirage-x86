# MIRAGE — conformance audit (2026-08-04)

> **A snapshot, kept for the record.** This is the audit as it was written on 2026-08-04. File and
> line references are those of the code on that date, and most of what it lists has been fixed since
> (items marked ✅ were already fixed when the audit was last edited). The current state is in
> [COMPAT.md](../COMPAT.md) and [ROADMAP.md](../ROADMAP.md).

An audit of the code base against the **x86 / DOS / CGA-EGA-VGA** specifications, along three axes:
compatibility, performance, maintenance. What prompted it: the `0x67` bug (an address-size prefix
consumed and then ignored, desynchronising the instruction stream), which took a whole day of
diagnosis.

## The central finding: the *silent falsehood*

The three audits **independently found the same pattern**, at three levels:

| level | pattern |
|---|---|
| **CPU** | a prefix or a condition **decodes cleanly** and then does something other than the specification — no diagnostic |
| **Video** | registers are **stored but never consulted**; the geometry comes from a fixed table, not from the CRTC |
| **DOS/BIOS** | an unimplemented service **returns "success"** (CF unchanged) instead of an error |

`0x67` was not an isolated accident: it is **the dominant class of bug** in the code base.

And the structural cause is a single one: **the gates cannot see this class.** `conformance.js` is
single-instruction and 8088 only (so blind to the 386 and to multi-instruction flag stripping);
`golden.js` covers 20 demos by framebuffer fingerprint; `dos.js` (407 lines), `vfs.js` (169),
`xms.js` (104) and most of the INT 10h/16h/1Ah services of `bios.js` have **no automated coverage
at all**. Every defect listed here can be introduced — or fixed and then broken again — with the
gates **entirely green**.

## Tier 0 — silent corruption in the CPU (the most serious, the cheapest)

| # | Defect | File | Effect |
|---|---|---|---|
| **T0.1** | **A DIV/IDIV/AAM fault does not end the block.** `cpu.div*` calls `swInt(0)`, which does not throw; the rest of the block runs and the final `RET` **overwrites `cpu.eip`**, cancelling the interrupt on a stack that already holds an IRET frame. | `recompiler.js:956-957`, `:706`, `cpu.js:226-242` | **Critical.** Any guest with an INT 0 handler (DOS extenders, protections, error trappers) derails. `BOUND` (`:592`) does it correctly — the model to copy. |
| **T0.2** | **`66 98` / `66 99` decode CBW/CWD instead of CWDE/CDQ** (`sz` is never read). The length is right, so no desynchronisation, but the arithmetic is wrong. | `recompiler.js:638-639` | **Critical.** `CDQ; IDIV ECX` is *the* 32-bit signed division idiom: garbage quotients. The most likely to be hit by 386 code. |
| **T0.3** | **`66 60/61` (PUSHAD/POPAD) and `66 9C/9D` (PUSHFD/POPFD) push 16 bits.** ✅ `C2/C3/CA/CB`, `9A`, `EA`, `E8/E9`, `FF /2 /3 /4`, `C4/C5`, `0F B2/B4/B5` fixed (test386.asm POST 5-6, the real-mode section complete). Remaining: `8F`, `C9`, `CF`, PUSH/POP FS/GS. | `recompiler.js:588-591,642-643,632,697,704,683-699` | **High.** Desynchronises **the stack** (16 against 32 bytes) as soon as it is mixed with a real 32-bit push or a `RET`. |
| **T0.4** | **`0x67` is not applied to implicit addressing**: `REP MOVS/STOS/…` (ESI/EDI/ECX), `XLAT` (EBX), `LOOP/LOOPE/LOOPNE`, `JCXZ→JECXZ`. The fix in `7e1e162` closed the desynchronisation (ModRM) but **not the semantic half**. | `recompiler.js:974-1003,709,726-729` | **High.** `67 F3 A4` (the standard fast 386 copy) uses SI/DI/CX instead of ESI/EDI/ECX. |
| **T0.5** | **`BT/BTS/BTR/BTC` mask the bit offset even for memory operands.** In memory, x86 uses the **full signed** offset to address a bit string (`byte += bitofs>>3`). | `recompiler.js:1016-1023` | **High.** Every bitmap access (allocators, collision masks) falls back into the first word. |
| **T0.6** | **XMS "move block" writes into `u8[]` with no self-modifying-code check.** The only write path in the code base that bypasses invalidation — and it is *exactly* the path that swaps code overlays in. | `xms.js:66` | **High.** Stale compiled blocks run. (Also: a byte-by-byte loop, where `copyWithin` would be 10-50× faster and handle overlap; no bounds check.) |
| **T0.7** | **DAA/DAS**: wrong high-adjust threshold (`0x9f` applied to the old AL), and DAS loses the low-nibble borrow in CF. | `cpu.js:247-258` | Medium. Multi-byte BCD chains (scores, decimal printing). |
| **T0.8** | **`REP` is not interruptible and counts as 1 cycle.** `REP MOVSW` with CX=0xFFFF makes 64 K accesses while advancing `cpu.cycles` by 1; no PIT tick or IRQ can land in the middle. | `recompiler.js:974-1003` | Medium (timing). Skews the PIT model, starves IRQ- and raster-synchronised effects. |

Smaller but equally silent: `0F 20/21/22/23` consume a displacement when `mod≠3` (desynchronisation
on a non-canonical encoding); `FF /3` and `FF /5` with `mod=3` produce `sb[undefined]`, a `NaN`
address; `FE /2..7` decodes DEC instead of #UD; `FF /7` emits **nothing**; word and dword accesses
that straddle 0x9FFFF→0xA0000 bypass the planar logic.

**The rest of the flag def/use table was checked register by register and is correct** — no
over-declared `def` (the only direction that could strip a live writer). Only `BOUND` lacks
`cur.use |= lALL` (`recompiler.js:592`).

## Tier 2 — video: what breaks whole classes of games

**What is right, and should be left alone**: the EGA planar write pipeline is **correct** — the 4
write modes, the order rotate → set/reset → ALU → bit mask, the latches, the map mask
(`vga.js:44-66`). Better than many toy emulators.

| # | Defect | File | Effect |
|---|---|---|---|
| **T2.1** | **The geometry comes from a fixed table, not from the CRTC registers.** Only 0x0C/0x0D (start) and 0x13 (offset) are consumed; width and height come from `DIMS`, indexed by the INT 10h mode number. The **Misc Output register (0x3C2/0x3CC) does not exist at all**. | `vga.js:9,104-110` | **320×240 Mode X is literally unreachable** — *the* Mode X. 40 lines cut off the bottom of every Mode X game. The same for 320×400 and 360×480. |
| **T2.2** | **Line compare / split screen entirely absent** (CRTC 0x18, 0x07 bit 4, 0x09 bit 6). | `video.js:72` | Every hardware status bar above a scrolling playfield: **Keen, Prince of Persia, Duke 1/2, Cosmo**, and the demo idiom of a split-screen scroller. |
| **T2.3** | **Read mode 1 (colour compare) not implemented**; `gc[5]` bit 3, `gc[2]`, `gc[7]` stored and never read. | `vga.js:70-75` | EGA sprite masks and collisions are garbage. The most used of the missing Graphics Controller features. |
| **T2.4** | **Attribute controller: only the 16 palette registers exist.** Missing: 0x13 **pixel panning** (smooth scroll becomes 8-pixel jumps), 0x14 **Colour Select** (high DAC bits; fast fades have no effect), 0x10 mode control (blink), 0x12 plane enable, 0x11 overscan. **Port 0x3C1 (attribute read) is not registered and reads 0xFF**: a save/restore destroys the palette. | `vga.js:97-100` | High. |
| **T2.5** | **Text mode hard-wired to 80×25×8×16, page 0, blink masked.** 40 columns are drawn as 80; **pages are never switched** (AH=05 stores the page, the renderer always reads B800); **attribute bit 7 is masked**, so no blinking *and* no bright background; 43/50 lines impossible. Mode 7 (MDA) is invisible, and a retrace loop on 0x3BA **loops for ever** (the port is not registered and reads 0xFF). | `video.js:8,86-114,94` | High and very visible. |
| **T2.6** | **INT 10h `AH=0Ch`/`0Dh` (write/read pixel) absent**, swallowed by `default:`. | `bios.js:146-266` | A **completely empty** graphics screen, without an error, for any program that draws through the BIOS. |
| **T2.7** | **No text in EGA/VGA graphics modes.** `teletype` handles only CGA modes 4/5/6; in 0Dh/12h/13h it writes character/attribute cells into B800 that nothing draws. | `bios.js:121-138` | Every "Loading…", banner or error message of a graphical game is **invisible**. |
| **T2.8** | **No horizontal blanking**: bit 0 of 0x3DA is set only during the 12 % of vertical blanking, instead of about 20 % of **each** of the 449 lines. | `bios.js:337-345` | Breaks every per-scanline raster effect (copper bars, mid-frame palette changes, wobble). A first-order demo breaker. |
| **T2.9** | **The CRTC is not reset on a mode change**: one mode's geometry leaks into the next (a sheared or shifted picture after going Mode X → 13h and back). | `vga.js:30-37` | Any program that changes mode more than once. |
| **T2.10** | **Sequencer: only registers 2 and 4.** Missing: register 0 (reset), register 1 (**bit 5 = screen off**, widely used), register 3 (character map select). Reading an index other than 2 or 4 returns `0` instead of the state, so save/restore corrupts. **DAC**: one latch shared between reading and writing, so read-modify-write fades desynchronise the channels; 0x3C7 and 0x3C6 are stubs. | `vga.js:78-88`, `bios.js:297-310` | Medium. |

## Tier 3 — performance and maintenance

- **The port bus is a `Map` on the hot path** (`machine.js:147-150`). `IN AL,0x3DA` is **the hottest
  port access in a DOS game** (every vsync loop), and it pays a `Map.get`, a megamorphic call (39
  handlers) and two ternaries. The block cache was already moved out of a `Map` for this exact
  reason (`recompiler.js:63-66`); the port bus never was. → a flat array and specialised
  `ioRead8/16/32` (the size is known when the code is emitted).
- **Self-modifying-code `invalidate` is O(blocks in the page)** per write; combined with the trap
  flag path, which **recompiles at every instruction**, it is the engine's worst profile (Lemmings:
  about 1593 trap-flag writes).
- **`translate()` is 735 lines long** (68 % of `recompiler.js`), four nested `switch` statements,
  about 25 helper closures. **Not unmanageable yet, but at the limit** — to be split when DPMI and
  protected mode force it, not before.
- **The MZ-EXE parser exists three times, identically** (`dos.js:121/193/230`) — and the
  `e_maxalloc` fix (`98c25f0`) was applied to only **one** copy: the drift has already happened.
- **Contradictory documentation**: `DEVICES.md:44` and `COMPAT.md:188` say "no XMS" while `xms.js`
  ships; the line-count table of `ARCHITECTURE.md` is out of date throughout; `TESTING.md` says
  "72 cases" against **83** real ones.

### Larger pieces of work (by risk and impact)

1. **A DOS/BIOS test suite** (`tools/test-dos-api.js`) and **a text-mode fingerprint in
   `golden.js`**. **This is the prerequisite for everything else**: without it, `dos.js`, `vfs.js`,
   `xms.js` and `bios.js` stay untested and every fix above can rot in silence.
2. **Geometry derived from the CRTC, and the Misc Output register** → unlocks **320×240 Mode X**
   (the largest video gap), 320×400, and tweaked text modes.
3. **Line compare / split screen** and **pixel panning** → Keen, Prince of Persia, Duke, demo
   scrollers.
4. **INT 13h and a virtual disk image** → Lemmings and every title on a diskette; removes the most
   dangerous silent no-op.
5. **A real MCB allocator** (first fit, coalescing, a validating `AH=49h`, PSP:0002) → fixes the
   leak on a non-LIFO free and the `4Ah` overlap.
6. **A per-scanline beam model** (horizontal blanking) → raster effects.
7. **Text mode flexibility** (40 columns, pages, 8×8 and 8×14 fonts, 43/50 lines, mode 7).
8. **Splitting `translate()`** — to be done *at the start* of the DPMI work, not on its own.

### Recommendation

Do quick wins **1 to 6 first**: they are exactly the `0x67` class (silent falsehoods, in the CPU, a
few lines each), and **number 1 makes visible** everything the audit could not reach. Then **the
first larger piece (the DOS/BIOS tests)** before attacking the rest; otherwise the fixes pile up
unguarded.
