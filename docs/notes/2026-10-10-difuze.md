# Difúze was never wrong: comparing at equal ticks with an unthrottled reference

## Symptom

On 2026-10-09, `node tools/dosdiff.js intros/difze.com <K>` showed DOSBox-X drawing Řrřola's
reaction–diffusion patterns while MIRAGE drew horizontal bands. QEMU, watched in real time, also
showed patterns. Difúze went into KNOWN-ISSUES as "draws horizontal bands; cause not found", and was
left out of the examples. The same tool had earlier put Puls, Symetrie and Dírojed in KNOWN-ISSUES
as "fewer instructions per tick than DOSBox-X".

## Hypotheses

1. An instruction Difúze relies on is wrong: it uses SHLD/SHRD, XADD, AAM 16, AAD 32, an SS-prefixed
   XLATB, LFS, and SAR by a CL whose upper bits must be masked off.
2. A block-level optimisation (dead-flag elimination) changes a value an instruction-level run would
   not.
3. Nothing is wrong, and the two machines were compared at different points in the program.

## Measurements

- MIRAGE, blocks against MIRAGE, one instruction at a time: the u and v arrays (two 64 KiB segments)
  hash the same at the end of frames 1 and 2. Hypothesis 2 is out.
- MIRAGE against Unicorn (QEMU's CPU core), started from the same 1.1 MB memory image and registers,
  with INT 10h and the I/O ports stubbed alike: the same hashes at frames 50, 100, 150, 200, 250, 300,
  for the Riverwash party version and for the final version. Hypothesis 1 is out.
- One frame of Difúze is 3.44 million instructions. MIRAGE's timer ticks every 182,584 instructions,
  so a frame is about 19 ticks. `dosdiff.js` runs DOSBox-X with `cycles=max`: as many instructions
  per tick as the host can execute, tens of frames per tick. At "K ticks" the two machines are
  hundreds of frames apart, and Difúze's first hundred frames are a band.
- MIRAGE's own screen at frames 100, 400, 1000, 2000: a band, spots, cells, then the next rule. The
  patterns are there.
- The same mistake on Puls (2026-10-09): with DOSBox-X at a FIXED 3,323 cycles per millisecond —
  MIRAGE's 182,584 instructions per tick, at 18.2 ticks a second — the two screens matched 99.8% at
  100 ticks, against 62% at `cycles=max`.

## Cause

Hypothesis 3. "The same number of ticks" means the same moment only if both machines execute the
same number of instructions per tick, and `cycles=max` makes DOSBox-X's rate depend on the host.
This is the fourth conclusion drawn from host-dependent timing in this project.

## Fix

No code was wrong. `tools/dosdiff.js` takes `DDCYCLES` (for instance `DDCYCLES="fixed 3323"`) so a
comparison can be made at MIRAGE's instruction rate, and its header says when that matters.
KNOWN-ISSUES loses both entries; Difúze joins the examples.
